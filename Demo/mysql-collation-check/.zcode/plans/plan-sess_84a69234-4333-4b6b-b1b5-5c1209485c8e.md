## 字段级排序规则修复方案

### 问题
当前 `MODIFY COLUMN` 只拼了 `{column_type} CHARACTER SET utf8mb4 COLLATE ...`，会丢失 `NOT NULL`、`DEFAULT`、`COMMENT`、`AUTO_INCREMENT` 等属性，导致严格模式报错或数据丢失。

### 方案

#### 1. 后端：从 `information_schema.COLUMNS` 获取完整列定义
用 `SHOW CREATE TABLE` 或查询 `information_schema.COLUMNS` 的更多字段来重建完整的列定义：

```sql
SELECT COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE, COLUMN_DEFAULT, 
       EXTRA, COLUMN_COMMENT, CHARACTER_SET_NAME, COLLATION_NAME
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = %s AND TABLE_NAME = %s
```

拼接逻辑：
```python
# varchar(255) NOT NULL DEFAULT '' COMMENT '用户名' CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci
definition = f"{col_type} {'NULL' if nullable == 'YES' else 'NOT NULL'}"
if default is not None:
    definition += f" DEFAULT {default}"  # 需处理 NULL vs 字符串
if extra:
    definition += f" {extra}"            # auto_increment, on update current_timestamp 等
if comment:
    definition += f" COMMENT '{comment}'"
definition += f" CHARACTER SET utf8mb4 COLLATE {TARGET_COLLATION}"
```

#### 2. 后端：新增批量修复字段接口
`POST /api/fix_all_columns` — 类似 `fix_all_tables`：
- 入参：`database`, `table`, `threshold`
- 查出该表所有需要修复的字段
- 逐个 `MODIFY COLUMN`（每个都是独立 ALTER，MySQL 不支持多列 MODIFY）
- ALTER 前检查行数，超阈值跳过
- 返回修复/跳过/失败结果
- 记录到 `fix_history.json`

#### 3. 后端：修复单字段接口
更新 `fix_column_collation` 使用完整的列定义拼接，而不是只传 `column_type`。

#### 4. 前端：列详情卡片增强
- 统计栏：总字段数 / 已符合 / 需修复
- 表头加「一键修复所有字段」按钮 + 阈值输入
- 「一键修复」弹窗展示每行的精确行数，超阈值标跳过
- 单字段修复按钮保持不变

#### 5. 前端：表列表增加字段级修复入口
表列表的「操作」列增加「修复字段」按钮，点击后进入列详情并自动触发批量修复。
